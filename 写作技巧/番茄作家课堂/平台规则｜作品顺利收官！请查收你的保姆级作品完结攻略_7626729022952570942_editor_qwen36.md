# 《科武纪元》编辑学习官｜平台完结规则萃取报告

## 1 课程核心判断（≤6条）
1. **推荐阈值绑定**：完结无硬性字数门槛，但强烈建议≥8万字（已开启推荐）后申请，否则永久损失推荐流量池。
2. **状态绝对锁定**：申请完结不可撤销；正文编辑权限永久关闭；不可新增章节/番外。
3. **无“完结推”机制**：完结不触发额外推流，流量波动完全依赖算法对内容质量的实时评估。
4. **完结偏好匹配**：完结后读者增量源于算法向“偏好完整阅读”的用户池倾斜，非平台福利。
5. **多书名实验强限制**：100万字以下已完结作品禁止开启实验；≥100万字完结可开但需同时满足5项条件。
6. **驳回可逆但成本高**：烂尾/仓促被驳回后，需补全内容方可二次申请，期间作品处于“未完结”但不可正常更新状态。

## 2 可执行编辑规则（按文章实际内容取舍）
| 维度 | 规则提取（基于平台完结逻辑） |
|:---|:---|

| **节奏** | 8万字为推荐分水岭。完结申请前需确保主线节奏已自然收束，禁止为凑字数注水拖沓，或为赶完结强行砍线。 |

## 3 科武适配：可用点 vs 不可硬套点
### ✅ 可用点（《科武纪元》长篇/短故事/热点稿）
- **长篇科幻**：利用“8万字推荐门槛”规划卷纲，前3卷完成世界观奠基与武道体系自洽，确保完结时设定不崩。
- **短故事/热点稿**：若未达8万字或处于冷启动期，严禁提前完结；应利用“驳回可补”机制，在审核期外完成结构补全。
- **多书名测试**：完结前（20-50万或≥100万区间）可开启一次多书名实验，测试“硬核科幻”与“热血武道”标签的流量转化率。

### ❌ 不可硬套点
- **依赖完结冲量**：平台无“完结推”，科幻长篇不可将“完结”作为流量杠杆，需靠内容质量维持算法推荐。
- **完结后迭代设定**：科幻设定常需参数校准或体系补丁，但“完结后不可修改正文”彻底封死后路，所有技术/武道逻辑必须在申请前冻结。
- **番外补坑**：平台要求“写完番外再申请”，科幻长篇若依赖番外解释核心设定，将因正文锁定导致主线逻辑残缺，触发烂尾判定。

## 4 编辑检查表（提交前必核）
1. [ ] 字数≥8万且已实际进入推荐池？
2. [ ] 核心主线冲突是否已闭环？无悬而未决的废线？
3. [ ] 科幻设定/武道体系是否在结局实现逻辑自洽？
4. [ ] 所有关键伏笔、人物弧光是否已回收/落地？
5. [ ] 是否已写完并定稿所有番外/补充设定？（完结后不可新增）
6. [ ] 是否确认不可撤销、不可修改正文、不可新增章节？
7. [ ] 是否避开断更/隐藏状态直接申请？（会触发状态强制重置）
8. [ ] 若计划多书名实验，是否已核对字数区间、实验次数与60天冷却期？

## 5 对作家角色的输入要求
| 维度 | 平台规则映射的硬性输入要求 |
|:---|:---|
| **动作链** | 必须按单向流程执行：`主线收束 → 伏笔回收 → 番外定稿 → 平台路径提交 → 等待3工作日审核`。禁止逆向操作或边更边改。 |
| **物理反馈** | 提交瞬间系统锁定正文编辑权限；3个工作日内状态变更为「已完结」；若原为断更/隐藏状态，提交后强制解除并公开。 |
| **代价** | 误操作或烂尾将导致：永久丧失修改权/番外创作权；<100万字作品永久丧失多书名实验资格；驳回需重写补全，消耗时间与推荐期流量。 |
| **钩子** | 前8万字必须铺设可支撑完整结局的核心悬念/体系钩子。钩子未闭环或中途断裂，将导致推荐期流量无法转化为完结长尾，直接触发审核驳回。 |
| **读者预期** | 完结标签仅匹配“偏好完整阅读”的用户池。读者预期为“设定闭环+人物落地+无烂尾”，非“额外福利”“流量爆发”或“后续补丁”。 |
