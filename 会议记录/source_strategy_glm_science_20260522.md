### 优先级逻辑

- **P1-2**（预印本+政府报告）：原创数据源头，不可替代。一次采集，多次复用。
- **P3-4**（专业+科技媒体）：二次解读，快速锁定热点+人话版，但需回溯原始来源交叉验证。
- **P5-6**（学术DB+国内媒体）：补充覆盖面；国内媒体时效好但需过滤营销噪声。
- **P7-8**（研报+社区）：低频高价值场景；财经敏感度用户关切，社区可挖争议点。
- **P9-10**（百科+社媒）：填充基础背景，非主力。

## 3. 过滤规则

### 3.1 入库门槛
- **必须有量化数据**：温度/功率/距离/延迟/预算/产能，至少一项可写入正文。
- **必须有小说映射锚点**：采集时即标注可映射的卷/章/变量，无锚点不入素材卡。
- **时效窗口**：
  - 预印本/学术论文：≤12个月
  - 政府报告/预算：≤18个月
  - 新闻/时事：≤7天（超期降级为背景参考）
- **去重**：采集前查INDEX.md + RAG，已有同源素材卡的不重复采。

### 3.2 噪声过滤
- **纯产品发布/营销稿**：除非涉及关键供应链（如芯片制程突破、光模块量产），否则过滤。
- **纯政治口号/声明**：无具体政策文本/预算数字的声明不采。
- **泛科普/鸡汤**：量子计算"将改变一切"类空洞文章不采；需写明具体参数/限制。
- **游戏/消费电子**：除非映射到军事模拟/训练场景，否则不采。

### 3.3 财经敏感度处理
- 财经新闻涉及股价/估值/融资：只提取**技术参数和产业趋势**，不写入具体股价/市值。
- 芯片/算力相关的出口管制、制裁清单：标记为"制度博弈"类，映射到铁幕线。
- 宏观政策（能源/电力/水）：提取配额数字和调度逻辑，映射到"算力=电/热/水"。

## 4. 交叉验证规则

### 4.1 强制交叉
以下变量**必须至少2个独立源**确认才可入素材卡：

| 变量 | 最低验证源组合 |
|------|-------------|
| 军事技术参数（射程/功率/延迟） | 官方报告 + 专业媒体 或 2篇同行评审 |
| 量子计算里程碑（比特数/相干时间/保真度） | 预印本 + 机构新闻稿 |
| 芯片/供应链数据（制程/产能/良率） | 厂商财报/公告 + 第三方研报 |
| 能源/聚变参数（温度/时间/净增益） | 实验室论文 + 官方新闻 |

### 4.2 海外源交叉验证
- **国内首发消息**（新智元/量子位/观察者网）：必须用arXiv/官方原文交叉验证数字，国内媒体常见夸大/翻译误差。
- **海外独家消息**（TechCrunch/Defense News）：如涉及中国相关技术，补充国内官方源验证，防断章取义。
- **社媒/社区信息**（X/Reddit/HN）：不可作为唯一源；必须追溯到原始论文/报告/官方声明。

### 4.3 冲突处理
- 同一数据不同源数字矛盾：取保守值，标注来源差异，素材卡记"上限/下限"。
- 国内与海外数据量级差异>20%：标记为"待验证"，不入正文。

## 5. 每日采集配额建议

| 配额项 | 建议值 | 说明 |
|--------|:---:|------|
| **每日总采集条数** | 15-25条 | 含原始URL，去重后有效 |
| **其中预印本/论文** | 5-8条 | OpenCLI arxiv_search + semantic_scholar |
| **政府/军方报告** | 2-3条 | 低频但高价值，遇重大发布可增至5 |
| **专业媒体新闻** | 5-8条 | RSS自动抓取+关键词过滤 |
| **国内媒体** | 3-5条 | 微信公众号爬虫，侧重军工/量子/芯片 |
| **每日转素材卡上限** | 8-12张 | 并非所有采集都需转卡 |
| **每日RAG入库** | 与素材卡同步 | 转卡即入库，不额外占用 |

### 配额执行原则
- **优先填缺口**：查INDEX缺口列表 + 大纲待补证标注（如大纲V8.12.7的"待补证再入"清单），有缺口先填。
- **勿为采而采**：无小说锚点的科学新闻不采；纯好奇心驱动的不采。
- **批量日 vs 维护日**：
  - 批量日（周一/三/五）：侧重arXiv + OpenAlex结构化检索。
  - 维护日（周二/四/六）：侧重RSS新闻流 + 财经/政策快讯。
  - 周日：不采，只整理/去重/更新INDEX。
