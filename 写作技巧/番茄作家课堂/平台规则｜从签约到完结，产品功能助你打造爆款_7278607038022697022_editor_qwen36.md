# 《科武纪元》编辑学习官｜平台规则提炼

## 1 课程核心判断（≤6条）
1. **流量纯算法驱动**：单书流量仅取决于作品状态（更新频率、质量达标、合规性、读者偏好），无人为干预或编辑控流。
2. **字数节点即功能阈值**：3w（书荒话题匹配）→8w/15w（首推开启）→10w（大流量池跃迁死线）→20w（多书名实验/头条标题）→100w（二次实验）。
3. **持续更新是核心杠杆**：3日内有更新记录是维持推荐资格、解锁实验功能的硬性条件；断更直接切断流量池跃迁。
4. **标题/封面需数据化验证**：多书名实验与头条标题推荐是平台提供的A/B测试工具，最优解由读者点击率（CTR）决定，非主观判断。
5. **互动数据决定私域基建**：互动UV≥200、阅读时长≥120min激活粉丝榜；1000粉解锁粉丝群。社区活跃度反哺算法留存权重。
6. **首推仅为质量探针**：8-15万字首推表现不佳不判死刑，需拉长篇幅至20w+解锁更多流量工具，以持续供给换取算法二次验证。

## 2 可执行编辑规则（按原文逻辑取舍）
| 维度 | 规则提取（基于原文） | 长篇科幻/短故事/热点稿应用 |
|:---|:---|:---|
| **开篇** | 头条标题公式反推：15-30字内，信息完整+画面感+数字/悬念，拒震惊体。 | 长篇：首章需提炼核心科武设定+冲突；短/热点：开篇300字必须抛出可被15字概括的强钩子。 |
| **节奏** | 8w手动/15w自动首推，10w持续更新是跃迁大流量池唯一硬指标。 | 长篇：前10w必须完成世界观落地+主线推进；短/热点：压缩至3-5w内完成首推测试，靠高频更新维持推荐池。 |
| **冲突** | 书荒推书要求“对比反转/冲突点”，需前置至显眼位置。 | 每章结尾/卷末必须设置可提取为推书文案的显性冲突（如：科技碾压vs武道反杀、理性计算vs人性抉择）。 |
| **人物** | “真实感受”共鸣要求人物动机可被一句话提炼，用于话题匹配。 | 人物弧光需绑定具体科武行为（如：为保算力牺牲肢体、为武道突破背负债务），避免抽象抒情。 |
| **题材** | 3w自动匹配书荒话题，依赖“高频低供关键词”抓取。 | 提前在简介/前3章埋设平台稀缺标签（如：硬科幻+古武、赛博修真、星际武道），供算法精准分发。 |
| **改编** | 原文未涉影视/短剧改编。以“多书名实验”替代为IP向市场测试逻辑。 | 20-50w区间准备3组书名（正剧向/爽文向/短剧向），用CTR数据验证IP改编潜力，非主观押注。 |
| **平台规则** | 严禁标题党/违规内容；头条标题禁带“第X章”；流量仅取决于作品状态。 | 所有外发文案/标题需过审合规；短/热点稿需避开敏感词；长篇需严格对齐推荐期更新频率。 |

## 3 科武适配：可用点、不可硬套点
| 维度 | 可用点（直接复用） | 不可硬套点（需规避/改造） |
|:---|:---|:---|
| **长篇科幻《科武纪元》** | 10w字跃迁逻辑完美匹配“科武体系初成+首战验证”节点；多书名实验可测试“硬核科幻”与“武道爽感”的市场偏好；头条标题公式可提炼为“技术代差+武道破局”的强画面钩子。 | 不可用“震惊体/情绪煽动”包装硬设定；不可为凑互动UV强行水日常；不可在头条标题塞入复杂科武术语（算法无法识别长尾词）。 |
| **短故事** | 依赖书荒话题匹配+头条标题快速起量；15-30字标题公式直接作为短故事核心卖点；高频更新维持3日推荐资格。 | 短故事无法触及10w/20w功能阈值，不可依赖“多书名实验”或“粉丝群”；需将冲突极度前置，放弃长线铺垫。 |
| **热点稿** | 利用“开书灵感”定位高频低供关键词；推书文案套用“权威+数字/对比反转”公式快速蹭流量池。 | 热点稿生命周期短，不可套用长篇“持续更新至10w”逻辑；需严格规避价值观争议，否则头条审核直接下架。 |

## 4 编辑检查表（10条以内）
- [ ] 8万字前是否完成核心科武设定抛出与首波悬念铺设？
- [ ] 是否保持3日内有更新记录，维持推荐池与实验资格？
- [ ] 10万字节点是否达成“读完率”基准线？（决定大流量池准入）
- [ ] 书荒推书文案是否避开震惊体，采用“概念+冲突+数字/悬念”结构？
- [ ] 头条推荐标题是否严格控制在15-30字，含画面感/数字/核心矛盾？
- [ ] 20-50万字区间是否准备3组差异化书名/封面进行A/B测试？
- [ ] 互动数据（章评/段评UV）是否≥200以激活粉丝榜？
- [ ] 内容是否严格规避违规词、负向价值观及“第X章”字样？
- [ ] 首推数据不佳时，是否已制定“拉长篇幅+优化题材标签”续写策略？
- [ ] 粉丝群/称号运营是否基于1000粉门槛提前规划私域话术？

## 5 对作家角色的输入要求
| 维度 | 平台逻辑映射 | 作家必须交付的输入标准 |
|:---|:---|:---|
| **动作链** | 算法按章节拆解留存节点，需明确因果序列。 | 每章必须提供“触发条件→科武行为→结果反馈”的完整链条，禁止断裂式跳跃或纯心理描写填充。 |
| **物理反馈** | 支撑“读完率”与互动UV，需具象化可感知。 | 科武设定必须伴随可量化的物理反馈（如：能量过载导致装甲熔毁、经脉负荷引发器官衰竭），拒绝抽象战力膨胀。 |
| **代价** | 算法惩罚“无损耗升级”，代价决定10w后留存。 | 每次力量突破/技术跃迁必须绑定明确代价（资源枯竭、寿命折损、阵营背叛），维持张力至大流量池。 |
| **钩子** | 需符合书荒推书公式，便于提取为头条标题。 | 章末/卷末必须设置可被15-30字概括的悬念或反转（如：“他启动跃迁引擎，却发现坐标指向母星坟场”），禁止开放式留白。 |
| **读者预期** | 3w自动匹配题材标签，首推期兑现承诺否则降权。 | 严格对齐简介/标签承诺的科武基调（硬科幻/武道升级/星际争霸），前3万字必须交付核心体验，不可挂羊头卖狗肉。 |
