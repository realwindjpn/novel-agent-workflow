## 一、动作链（写作时立即可执行）

### 开篇执行序列

```
▸ 动1：动笔前先确认“核心冲突种子”已写入第1章前500字
   → 检查：主角必须面临“可量化威胁”或“明确缺失”
   → 错误标志：开篇无摩擦、无挑战、无缺失

▸ 动2：写完首章后不回头，立刻写第2章开头
   → 规则：首章不完美是预设值，60分即可发布
   → 正确操作：写完→发布→次日复盘→标记可优化点

▸ 动3：每日写作前先回顾昨日“标疑点”列表
   → 执行顺序：先解决1个疑点→再写新内容→写完再标疑点
   → 禁止行为：为了完美解决疑点而停笔
```

### 卡文破局序列

```
▸ 触发条件：连续30分钟无法推进情节

▸ 执行步骤：
  ① 立即在文档中输入：[卡点] + 当前状态描述 + 3个可能走向
  ② 选任意一个走向继续写（不选最优解）
  ③ 写完当前场景后，在结尾标注：[待修复]具体问题
  ④ 第二天执行删改，不是继续卡文

▸ 禁止操作：翻资料、刷视频、找灵感、停更
```

### 读者反馈处理序列

```
▸ 触发条件：同一类型评论出现≥3条

▸ 执行步骤：
  ① 归类：统计评论指向（情绪型/逻辑型）
  ② 判断：
     → 情绪型（“太虐”“不喜欢男主”）→记录但不动笔
     → 逻辑型（“战力崩了”“设定矛盾”）→进入修复队列
  ③ 修复必须附带“逻辑补丁”说明，禁止单纯删改
  
▸ 禁忌：因单条情绪评论修改人物命运
```

### 科武战斗描写序列

```
▸ 动1：启动前先确认“代价类型”
   → 例：神经负荷型 / 能量消耗型 / 冷却延迟型

▸ 动2：战斗流程必须包含以下步骤
   ① 环境感知（敌方位置、能量读数、物理距离）
   ② 决策判断（选最优方案而非主角开挂）
   ③ 执行反馈（每个动作必须有感官/数据描写）
   ④ 代价触发（必然出现，非可选项）

▸ 动3：战斗结束必须有“未解问题”
   → 例：能量读数异常 / 敌方信号未断 / 盟友状态失联
```

## 二、反馈机制

### 写作过程反馈

| 动作 | 正确信号 | 错误信号 |
|:---|:---|:---|
| 写场景 | 推进了情节 + 埋了新钩子 | 卡在原地改细节 |
| 写对话 | 推动冲突 + 暴露信息差 | 两人聊天无目的 |
| 写战斗 | 有代价 + 有意外 | 无代价 + 主角必胜 |
| 卡文处理 | 产出草稿 + 标记疑点 | 寻找灵感 + 停笔 |

### 读者数据反馈

```
▸ 屏蔽期（前20万字）：
  → 不看后台数据
  → 只看评论条数和归类

▸ 开放期（20万字后）：
  → 关注完读率变化趋势，不看单日数据波动
  → 关注“加入书架”率，不关注当日收益
  → 30万字节点若完读率下跌→检查前30章逻辑漏洞
```

### 预期兑现反馈

```
▸ 小预期（10章）：
  → 是否兑现？→是→继续；否→在下5章内补足

▸ 大预期（30章）：
  → 偏差率计算：预期结果 vs 实际结果
  → 偏差>15%→在章节末加“补救铺垫”
  → 偏差<15%→进入下一预期周期
```

## 三、代价系统

### 违反规则的代价

| 规则 | 违规行为 | 代价 |
|:---|:---|:---|
| 卡文执行 | 停笔超24小时 | 推荐权重下降，追读流失 |
| 读者反馈 | 因情绪评论改人物命运 | 设定崩塌，核心读者流失 |
| 战斗描写 | 跨步骤跳跃/无代价开挂 | 爽感透支，战力体系崩坏 |
| 章末钩子 | 纯情绪收尾 | 点击率下降，读者流失 |
| 产能纪律 | 日更低于4k | 触发平台降权，断推荐池 |

### 能力/设定的代价模板

```
▸ 神经增幅类：
  代价 = 战后神经延迟（XX小时）+ 感知阈值永久提升

▸ 能量武器类：
  代价 = 充能时间（X分钟）+ 能量核心寿命损耗

▸ 阵营行动类：
  代价 = 道德负债 / 盟友信任损耗 / 未来行动受限

▸ 科技突破类：
  代价 = 稀有资源消耗 / 技术代际倒计时 / 敌方复制风险
```

## 四、失败模式识别

### 常见失败模式清单

**1. 开篇失败模式**
```
标志：前三章无核心冲突，无明确目标，无可量化威胁
结果：读者在推荐页划走，不进入书架
修复：重写第1章第1段，确保第1句出现冲突元素
```

**2. 卡文失败模式**
```
标志：停笔找灵感超过12小时，开始刷同类作品找感觉
结果：断更或低质更新，推荐权重受损
修复：强制执行“卡文破局序列”，哪怕产出垃圾也要写
```

**3. 战斗描写失败模式**
```
标志：
  → 战斗流程跳过步骤（如：发现敌人→直接击中）
  → 主角无代价获胜
  → 无量化数据反馈（无距离/速度/能量/损伤数值）
结果：爽感透支，战力体系崩坏，读者失去期待
修复：用“战斗描写序列”重建完整流程
```

**4. 读者反馈处理失败模式**
```
标志：
  → 因单条情绪评论修改核心人物命运
  → 删除不合理情节但不补逻辑补丁
结果：设定崩塌，引发更大规模负面评论
修复：所有修改必须附带“逻辑补丁说明”，发布前自审3遍
```

**5. 钩子失败模式**
```
标志：章末用情绪收尾（如“他的心很痛”“她忍不住流下眼泪”）
结果：读者无点击动力，第二天追读率下降
修复：每个章末必须包含“未解变量”（见钩子类型）
```

## 五、人物口吻（科武语境）

### 核心角色口吻模板

```
▸ 军人/战士型：
  语速快，短句为主，优先描述物理状态
  例：“三秒后落地，冲击值预计超骨骼极限，别抱期望。”

▸ 科学家/技术型：
  冷静，数据化，先说结论后解释
  例：“能量转化率68%，是理论上限的71%。没有奇迹。”

▸ 指挥官/政客型：
  省略情感描述，优先利益计算
  例：“你的私人问题不在我的考虑范围内。回答我，能执行吗？”

▸ 激进者/反叛型：
  否定式句式，挑衅，挑衅性的反问
  例：“所以你打算用'规则'解释一切？规则是谁写的？”
```

### 对话禁止模式

```
✗ “他的眼神变得冰冷” → 无动作描写
✗ “她心中涌起复杂的情绪” → 无具体指向
✗ “他冷笑了一声” → 无因果逻辑

✓ 正确示范：
  “他的手指在扳机护圈上敲了两下。‘你说完了？’”
  “她盯着能量读数，瞳孔收缩。‘……这不可能。’”
```

## 六、段落节奏模板

### 场景推进节奏

```
【节奏A：信息释放型】
▸ 第1段：建立环境/数据/状态（2-3句）
▸ 第2段：引入冲突变量（打破数据平衡的事件）
▸ 第3段：主角应对（展示能力/暴露缺陷）
▸ 第4段：代价触发（能力损失/情报泄露/时间压力）
▸ 第5段：悬念收尾（未解问题/意外变量）

【节奏B：情绪驱动型】
▸ 第1段：物理状态描写（先于情绪）
▸ 第2段：外部事件触发
▸ 第3段：身体反应（手抖/呼吸变化/痛觉）
▸ 第4段：简短对白（情绪压缩为2-3句）
▸ 第5段：悬念收尾
```

### 战斗场景节奏

```
▸ 触发：威胁出现（敌方信号/视觉接触/能量读数异常）
▸ 决策：2秒内完成（主角判断+缺陷暴露）
▸ 执行：分步骤展开（每个步骤有反馈）
▸ 转折：代价触发或意外变量出现
▸ 收尾：悬念钩子（非主角视角的未解问题）
```

### 章节节奏总览

```
▸ 开头（前10%）：建立本章核心冲突
▸ 中段（70%）：冲突升级+代价叠加+意外变量
▸ 结尾（20%）：情绪/悬念收尾+钩子

单章字数：2500-3500字
节奏标记：每800字插入一次“小悬念”避免阅读疲劳
```

## 七、章末钩子类型清单

### 科武长篇专用钩子

```
▸ 类型A：数据异常钩子
  结构：章节最后一句呈现异常读数/信号/数值
  例：“屏幕角落，坐标显示：未知。”

▸ 类型B：信号截获钩子
  结构：截获未解读的信息/频段/加密内容
  例：“数据包解压失败，发件人：未知。”

▸ 类型C：生理异常钩子
  结构：主角身体出现不可解释的反应
  例：“他的手背上，血管纹路正在以肉眼可见的速度蔓延。”

▸ 类型D：第三方视角钩子
  结构：以非主角视角呈现悬念信息
  例：“而此刻，在观测站的监控屏幕上，那个光点已经消失了三个小时。”

▸ 类型E：系统报错钩子
  结构：技术系统出现不可解释的错误
  例：“警告：核心协议冲突，来源——未知。”
```

### 情绪钩子禁用清单

```
✗ 禁用：以情绪状态收尾（“她的心碎了”“他感到绝望”）
✗ 禁用：纯内心独白收尾
✗ 禁用：事件总结式收尾（“这就是他命运转折的一天”）

✓ 强制：必须包含“未解变量”
```

## 九、章节自检清单（发布前执行）

### 基础自检（每章必查）

```
□ 1. 章末是否有“未解变量”钩子？
□ 2. 战斗/科技描写是否包含完整步骤序列？
□ 3. 能力使用是否绑定明确代价？
□ 4. 对话是否包含物理状态描写（非情绪标签）？
□ 5. 数据/数值是否有量化描述？
□ 6. 本章是否推动核心冲突向前？
□ 7. 章节字数是否在2500-3500区间？
```

### 进阶自检（每5章复查）

```
□ 8. 本章是否兑现一个小预期？或为下一个大预期铺垫？
□ 9. 是否有新设定/信息引入但未配套解释？
□ 10. 核心人物命运是否出现转折？→若是，检查：
     → 是否预留修改接口？
     → 是否已做读者情绪阈值预判？
```

### 逻辑自检（每10章复查）

```
□ 11. 战力体系是否一致？→检查战斗结果是否匹配已建立规则
□ 12. 科技设定是否自洽？→检查新科技是否与旧设定冲突
□ 13. 角色能力是否匹配？→检查主角是否因剧情需要突然获得新能力
```

### 发布前最终检查

```
□ 14. 章节末钩子是否为“未解变量”而非情绪收尾？
□ 15. 是否附上任务卡中的“逻辑补丁”说明？（如有修改）
□ 16. 是否检查字数达标（≥2500字）？
□ 17. 是否完成至少一次通读纠错？（错别字/标点/逻辑断层）
```

## 十、平台规则转风险门禁

### 发布前门禁检查

```
【门禁A：字数门禁】
→ 单章必须≥2500字
→ 当日更新必须≥4000字（若分章）
→ 断更不超过24小时
→ 违规代价：推荐权重降级，完读率统计偏差

【门禁B：内容门禁】
→ 禁止出现：血腥描写超标/政治敏感词/平台违禁词
→ 建议：敏感科技描写先查阅平台规则文档
→ 违规代价：章节被删，流量降权

【门禁C：节奏门禁】
→ 10万字前不允许完本
→ 30万字前不允许开启大结局线
→ 违规代价：平台判定为“不完整作品”，推荐权重受影响
```

### 包装风险门禁

```
【风险点1：书名/简介误导】
→ 书名包含的关键词必须在正文前3章兑现
→ 简介承诺的“爽点”必须在20章内出现
→ 违规代价：读者差评率上升，追读下降

【风险点2：标签与内容不符】
→ 若标为“科幻”，战斗/科技描写占比需≥40%
→ 若标为“机甲”，机甲操作细节需≥20%
→ 违规代价：平台调整标签，算法推荐精准度下降
```

### 数据风险门禁

```
【风险点1：数据焦虑触发】
→ 触发条件：连续3天看后台数据且日收<50元
→ 门禁操作：强制屏蔽后台24小时，专注写作
→ 违规代价：创作节奏被打断，质量下降

【风险点2：读者评论误导】
→ 触发条件：单条评论引发创作方向动摇
→ 门禁操作：归类为“情绪型”→忽略；归类为“逻辑型”→进修复队列
→ 违规代价：设定崩塌，核心读者流失

【风险点3：追读数据误判】
→ 触发条件：追读率单周下降超过20%
→ 门禁操作：检查前5章是否有逻辑漏洞，而非改核心设定
→ 违规代价：因错误归因导致错误的修复方向
```

## 十一、可借用标注

### 短故事/狼人篇可借点

```
✓ 直接借用：
  → “硬写→复盘→删改”卡文破局序列
  → 章节自检清单（基础自检8条）
  → 钩子类型清单（数据异常/信号截获/生理异常）
  → 人物口吻模板（情绪标签→物理状态描写）

△ 改编后借用：
  → 任务卡字段（缩减为：冲突/目标/钩子）
  → 代价系统模板（适配短篇篇幅）
  → 风险门禁（改编为“发布前必查”）
```

### 科武长篇专项可借点

```
✓ 完整保留：
  → 卡文破局序列（全流程）
  → 读者反馈处理序列（全流程）
  → 战斗描写序列（全流程）
  → 章节自检清单（17条全量）
  → 风险门禁（全量）

✓ 科武适配：
  → 代价模板（神经负荷/能量消耗/冷却延迟）
  → 钩子类型（数据异常/系统报错/第三方视角）
  → 段落节奏模板（战斗场景节奏）
```

### 平台规则类转风险门禁

```
→ 数据屏蔽期 → 前20万字不看后台门禁
→ 推荐池门槛 → 日更6k字数门禁
→ 读者反馈规则 → 评论归类门禁+逻辑型修复门禁

→ 剧情容错原则 → 人物命运转折门禁（必须预留修改接口）
```
