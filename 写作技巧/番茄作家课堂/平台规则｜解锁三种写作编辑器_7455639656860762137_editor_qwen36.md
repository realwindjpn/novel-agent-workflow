# 《科武纪元》编辑学习官｜平台规则精读笔记

## 1 课程核心判断（≤6条）
1. **三端同源，场景分流**：番茄作家助手APP（移动端碎片化）、番茄免费小说APP（读者端直发）、番茄小说网PC端（深度创作）功能一致，按设备与写作习惯择一即可。
2. **实名非强制，但决定商业化**：未实名可发文，但签约、APP搜索曝光、打赏/稿费结算均以实名认证为硬性前置。
3. **双轨发布机制**：“创建书本”（信息完备→建书→发文）与“去写章节”（先发章→后补信息）并行；未发布章节不进入审核，降低试错成本。
4. **AI工具链已嵌入工作流**：错字检索、大纲提示、扩写/改写/续写/起名/卡文锦囊覆盖创作全链路，但均有严格字数与指令限制。
5. **分类决定初始流量池**：创建时必须选定题材分类，PC端“小说”与“短故事”独立入口，错选将导致推荐算法错配。
6. **书名可改但需查重**：发布前/后均可修改书名，但系统强制查重，不可与站内已有作品重复。

## 2 可执行编辑规则（按文章实际内容取舍）
| 维度 | 规则提取（基于原文） | 执行说明 |
|:---|:---|:---|
| **开篇** | 原文未直接指导叙事技巧。但“去写章节”支持先发正文后补书名/封面。 | 允许用强钩子开篇快速测试市场，无需等全套包装完成。 |
| **节奏** | 平台明确建议“坚持每日更新”。 | 结合AI续写/卡文锦囊维持日更频率，断更将影响推荐权重。 |
| **冲突** | 原文未涉及。 | 不提取。 |
| **人物** | AI起名支持输入≤100字描述生成角色/物品名。 | 命名需人工核对与世界观一致性，禁止直接套用AI随机结果。 |
| **题材** | 创建时必须选择分类；PC端“小说/短故事”分流入池。 | 长篇科武选“小说”，热点短稿选“短故事”，严禁混用入口。 |
| **改编** | 原文未涉及。 | 不提取。 |
| **平台规则** | ①实名签约门槛 ②草稿<1000字仅能存草稿 ③未发布不审核 ④AI扩写限5-300字/改写限5-600字 ⑤分类必填 ⑥书名查重 | 发布前逐项核对；AI调用需分段输入；分类与简介必须与正文首屏标签对齐。 |

## 3 科武适配
### ✅ 可用点
- **AI卡文锦囊**：输入“科武设定卡点（如：灵能装甲过载阈值/古武经脉反噬机制）+后续情节简述”，可快速生成符合逻辑的过渡段落。
- **AI改写定向**：利用“严肃沉稳”方向统一科武基调，避免行文风格跳跃。
- **PC端“创建书本”流**：适合长篇科武的大纲先行、设定集同步录入，便于后续章节调用。
- **日更机制**：利用AI辅助维持长篇连载节奏，稳定追读数据。

### ⛔ 不可硬套点
- **AI扩写/续写字数限制（≤300字）**：无法承载长篇科武的复杂世界观推演、硬核物理/武道逻辑链，强行使用易导致设定崩坏或战力通胀。
- **“快速试水”逻辑**：科武长篇依赖严密设定与伏笔回收，不适合用“去写章节”盲目先发后补，易造成前后矛盾、读者流失。
- **短故事入口**：与长篇科武的连载属性冲突，不可将科武主线拆分为短故事发布，否则流量池错配且无法积累长篇订阅。

## 4 编辑检查表（10条以内）
- [ ] 是否已完成实名认证？（决定签约/曝光/收益）
- [ ] 发布前是否选定准确题材分类？（影响初始推荐池）
- [ ] 采用“创建书本”还是“去写章节”？（前者需备齐信息，后者可先更后补）
- [ ] 单章草稿字数是否≥1000字？（低于此值仅存草稿，无法发布）
- [ ] 书名是否通过站内查重？（不可重复，发布后可改）
- [ ] AI扩写/改写输入是否超限？（扩写≤300字，改写≤600字）
- [ ] AI生成内容是否经人工逻辑/设定校验？（防风格割裂与战力崩坏）
- [ ] 是否设置固定发布时间？（利用平台定时推荐机制）
- [ ] 长篇/短稿是否选对PC端入口？（“小说”与“短故事”独立分流）
- [ ] 未发布章节是否确认未触发审核？（避免半成品误入推荐流）

## 5 对作家角色的输入要求
（基于平台AI工具调用规范与科武题材特性，作家向编辑器/AI输入时必须满足以下结构化参数）

| 维度 | 输入要求 | 平台/科武映射 |
|:---|:---|:---|
| **动作链** | 必须提供“触发条件→执行动作→结果状态”完整序列，禁止跨步跳跃。 | AI续写/卡文锦囊依赖明确因果链，断裂将生成无效过渡。 |
| **物理反馈** | 输入需附带基础交互参数（如：动能转化效率/装甲损耗率/经脉负荷阈值）。 | 科武设定需可量化，AI改写时缺乏参数将输出“唯心”描写，破坏硬核感。 |
| **代价** | 每次关键行动/升级必须绑定明确资源消耗或生理/社会代价，并在大纲中标注节点。 | 平台算法偏好“有代价的成长”，无成本开挂将导致追读断崖。 |
| **钩子** | 章节末尾发布前，需预留1个未解悬念或状态突变（如：系统警报/功法反噬/敌袭信号）。 | 适配平台“追更”推荐逻辑，提升次日留存率。 |
| **读者预期** | 开篇3章内必须在题材选择、简介、正文首屏兑现核心标签（如“硬核机甲+古武”）。 | 分类与正文标签错位将导致推荐流量错配，跳出率飙升，算法降权。 |
