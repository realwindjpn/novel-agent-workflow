# 《科武纪元》编辑学习官｜平台规则学习报告

## 1 课程核心判断（≤6条）
1. **区分度决定破圈效率**：多书名实验的本质是人群测试，仅调换词序/同义词无法触达新流量池，必须切换风格或核心卖点。
2. **一致性决定留存底线**：书名噱头与正文内容错位会引发“骗点击”反噬，导致跳出率飙升、推荐权重断崖式下跌。
3. **实验是数据漏斗，非改名游戏**：流量变化取决于“新读者点击率→读完率→追更率”的转化链路，书名仅负责第一环。
4. **平台规则自动兜底**：违规书名由系统自动替换（最优/非最优组逻辑不同），作者需前置自查，不可依赖事后手动干预。
5. **读者端显示分层隔离**：老读者锁定原书名、实验期新读者锁定组内书名、实验后新读者锁定最优书名；搜索缓存仅影响前端展示，不干扰底层实验数据。

## 2 可执行编辑规则（按原文实际内容取舍）
| 维度 | 规则提取（基于原文） | 执行标准 |
|:---|:---|:---|
| **开篇** | 标题即内容承诺 | 首章前3000字必须出现书名核心意象/设定/情绪基调，禁止“标题引流+正文换皮”。 |
| **题材** | 实验组需正交测试 | 每组书名需覆盖差异化标签（如A组硬核科幻/ B组武道升级/ C组悬疑解谜），严禁跨题材硬蹭无关热词。 |
| **平台规则** | 数据监控与合规前置 | 实验期以“新读者留存”为核心指标；违规自动替换机制需预留Plan B；搜索缓存需用新设备/账号验证。 |
| **节奏/冲突/人物/改编** | 原文未直接涉及 | 基于“标题-内容一致性”原则推导：正文节奏与冲突密度必须匹配书名承诺的阅读预期，否则高跳出率直接拉低后续推荐流量。 |

## 3 科武适配
| 可用点 | 不可硬套点 |
|:---|:---|
| ✅ **卖点正交测试**：用多书名验证“科幻侧重”vs“武道侧重”（例：《星舰武道录》测硬核设定，《肉身破星》测热血升级），精准定位核心受众。 | ❌ **短平快热词硬套**：科幻长篇禁用“重生/校草/八零/霸总”等跨题材引流词，会直接污染科幻基本盘，触发平台降权。 |
| ✅ **分层显示利用**：实验期老读者不受干扰，可同步在作话/书友圈说明“书名测试中”，降低追更断层感。 | ❌ **实验替代正文**：多书名仅优化流量入口，无法弥补世界观割裂、战力崩坏或节奏拖沓；科幻长篇依赖逻辑连贯性，频繁改书名/封面会破坏IP沉淀。 |
| ✅ **合规自查前置**：科武设定易涉“暴力/敏感科技词”，实验前需逐字核对平台审核提示，避免自动替换导致定位模糊。 | ❌ **搜索缓存依赖**：长篇连载的SEO权重主要靠正文更新频率与完读率，搜索展示锁定机制对流量分发影响极微，不应作为运营重心。 |

## 4 编辑检查表（8条）
- [ ] 实验组书名是否在≥2个维度（题材侧重/核心卖点/情绪基调）具备明确区分度？
- [ ] 标题关键词是否100%匹配正文前三章核心设定与开篇事件？
- [ ] 是否已剔除跨题材引流词、夸大承诺词及平台敏感词？
- [ ] 是否已配置实验期数据监控节点（CTR、读完率、追更率、差评率）？
- [ ] 老读者端显示逻辑是否已做站内公告/作话说明？
- [ ] 最优书名固化后，封面/简介/标签是否同步迭代以匹配新定位？
- [ ] 搜索缓存验证是否使用未浏览过该作品的新设备/新账号？
- [ ] 实验流量下降是否已启动“标题-内容对齐度”复盘并准备Plan B？

## 5 对作家角色的输入要求
| 要素 | 输入标准（强制对齐平台规则） |
|:---|:---|
| **动作链** | 开篇动作必须直接触发书名承诺的核心事件（如书名含“机甲/武道”，首章必须有启动/交锋/锻造动作链），禁止纯设定堆砌或背景说明前置。 |
| **物理反馈** | 科武交互需具象化可感知细节（能量传导路径、金属疲劳形变、重力异常参数、神经负荷阈值），用物理反馈替代抽象描述，支撑“硬核/武道”标签。 |
| **代价** | 每次能力跃升/战斗胜利必须伴随明确损耗（装备折旧率、寿命折减、神经损伤、资源枯竭），杜绝无代价升级，维持长期追更张力与数据留存。 |
| **钩子** | 每章结尾钩子需与当前实验书名卖点强绑定（测“悬疑科武”留线索断点，测“热血升级”留战力突破临界点），确保点击流量转化为有效阅读。 |
| **读者预期** | 严格对齐实验组书名承诺的阅读体验：硬核科幻读者要逻辑自洽与设定严谨，武道读者要节奏爽感与成长反馈。标题引流与正文体验错位将直接触发平台降权。 |
