## 一、写作前任务卡字段更新

> **触发条件**：每次开新章节/新副本/新卷前，必须填写完毕方可动笔

| 字段 | 必填内容 | 验证标准 |
|:---|:---|:---|
| **本章核心事件** | ①事件名 ②推进主线/支线标识 | 不能留空 |
| **主角即时目标** | ≤20字可量化目标 | 含具体对象+数字指标 |
| **对手/障碍** | 势力/人物/规则/时间四种之一 | 必须对立存在 |
| **本章代价预设** | 触发代价类型（体力/资源/关系/信息） | 需影响后续≥2章 |
| **钩子类型** | 信息差钩/生存钩/升级钩三种之一 | 必须在结尾呈现 |
| **视觉化锚点** | 1个可短视频切片的名场面描述 | 需含感官细节 |
| **字数目标** | 3000-3500字区间 | 预留钩子插入空间 |

## 二、开篇动作包（强制执行）

### 2.1 短故事可借用：前300字闪电开篇

```
执行序列：
① 第1句 → 强动作/强冲突画面（禁止静态背景）
② 第50字 → 主角处境危机已触发
③ 第150字 → 核心矛盾双方已登场
④ 第300字 → 读者必须知道"这事不简单"
```

**失败模式**：开篇超过300字仍未出现冲突动作 → 重写

### 2.2 科武长篇专有：前三章钩子矩阵

| 章数 | 必须完成 | 验证指标 |
|:---|:---|:---|
| 第1章 | 世界观锚点 + 主角核心诉求 | 读者能说清"这是关于什么" |
| 第2章 | 金手指/武道体系初显 + 首个可量化的障碍 | 主角战力值需明确 |
| 第3章 | 首个不可逆危机 | 需有"回不了头"的代价 |

**门禁**：第3章结束时若主角未遭遇「不可撤回」的事件 → 触发重写警告

## 三、冲突构建动作包

### 3.1 阶梯式矛盾链（长篇用）

```
每卷必须包含以下四层，顺序不可跳：

Level 1 → 生存危机（饿狼/囚笼/追杀三选一）
Level 2 → 资源争夺（功法/装备/势力三选一）
Level 3 → 势力博弈（宗门/星际帝国/商业联盟三选一）
Level 4 → 规则颠覆（新法则曝光/旧秩序崩塌/核心秘密外泄）

每层升级必须附带「前层代价清算」
```

### 3.2 短故事可借用：一镜到底冲突法

```
执行模板：
起手 → 矛盾爆发（已死1人/已损失关键物）
展开 → 双方筹码展示（禁止打哑谜）
高潮 → 筹码归零/反转（必须有意外变量）
收尾 → 情绪升华（1句话点题）

总时长：3000-5000字/篇
```

### 3.3 冲突禁忌清单

- [ ] 禁止「势均力敌→突然胜利」的无代价爽点
- [ ] 禁止「敌人降智」以推进剧情
- [ ] 禁止「机械降神」（金手指现解现用）
- [ ] 禁止「战力通胀失控」（升级后前敌无意义）

## 四、节奏控制动作包

### 4.1 章节节奏模板

| 段落位置 | 时长建议 | 内容要求 |
|:---|:---|:---|
| 开篇50字 | 闪电进入 | 动作/冲突/悬念三合一 |
| 中段1000字 | 推进区 | 完成目标60%+信息释放 |
| 高潮500字 | 冲突峰值 | 代价明确化/局势逆转 |
| 结尾300字 | 钩子区 | 必须有「翻页理由」 |

### 4.2 战斗节奏拆解（科武专用）

```
标准战斗段落必须包含：

① 起手式 → 能量运转/机甲启动（消耗显化）
② 交锋轨迹 → 三回合起落（每回合有得失）
③ 环境破坏 → 物理反馈（第1回合场地损毁30%）
④ 胜负判定 → 代价结算（不只是胜负，还有后续账本）

禁止出现：「全力一击」「轻松化解」「毫发无伤」
```

### 4.3 日常节奏门禁

> **触发条件**：连续2章无战斗/无冲突/无升级

- [ ] 检查是否「水文化」
- [ ] 强制插入「资源短缺事件」或「新势力介入」
- [ ] 或压缩至番外/外传

## 五、代价-反馈循环（核心机制）

### 5.1 代价类型清单

| 类型 | 适用场景 | 必须量化 |
|:---|:---|:---|
| 体力代价 | 越级战斗/透支修炼 | 标注恢复时长 |
| 资源代价 | 丹药/能量块/武器损耗 | 标注剩余库存 |
| 关系代价 | 结仇/背叛/孤立 | 标注敌对势力 |
| 信息代价 | 暴露底牌/泄露秘密 | 标注后果延迟 |
| 时间代价 | 倒计时/季节限制 | 标注deadline |

### 5.2 代价账本规则

```
每笔代价必须入账：

① 写入当前章节的「结果反馈」栏
② 标注「影响范围」（短期1-3章/中期4-10章/长期贯穿）
③ 在后续≥2章内显化后果
④ 成为新冲突的「燃料」而非一次性消耗

示例：
「主角燃烧10年寿命越级」→ 第5章出现「经脉暗伤」→ 第12章因此输给宿敌 → 引发闭关修炼线
```

### 5.3 失败模式：代价通胀

- [ ] 单次战斗代价 > 主角承受极限的80%
- [ ] 代价未在后续剧情中持续影响
- [ ] 「禁忌代价」被多次使用且无累计后果
- [ ] 读者感受不到「爽点需要代价」的平衡

## 六、章节结尾钩子库

### 6.1 信息差钩子（优选）

| 类型 | 写法模板 | 示例 |
|:---|:---|:---|
| 新线索型 | 「他发现XX下面刻着YY的名字」 | 废机甲残骸上刻着父亲的帝国徽记 |

| 数据暗示型 | 「系统提示：YY条件已达成」 | 宿主绑定率99%，目标锁定 |

### 6.2 生存钩子（备选）

| 类型 | 写法模板 | 示例 |
|:---|:---|:---|
| 倒计时型 | 「还剩XX时间/次数」 | 星门能量只够最后一次跳跃 |

| 势力介入型 | 「第三方XX正在接近」 | 星际海盗团的舰队出现在视野边缘 |

### 6.3 钩子禁忌

- [ ] 禁止「开放式悬念」（如：未完待续）
- [ ] 禁止「伪钩子」（无后续承接的信息）
- [ ] 禁止「情绪钩子单独使用」（需配合情节悬念）

## 七、读者预期管理（广告分成核心）

### 7.1 承诺-兑现契约

| 开篇承诺 | 兑现节点 | 拔高阈值 |
|:---|:---|:---|
| 金手指初显 | 5万字内首次实质使用 | 需展示升级空间 |
| 核心目标初定 | 每卷需有阶段性进展 | 不可遥遥无期 |
| 世界观悬念 | 10万字内需释放30% | 不可「挖坑不填」 |
| 势力格局 | 每20万字需有格局重组 | 不可「一成不变」 |

### 7.2 预期失控警告线

- [ ] 开篇承诺到10万字仍未兑现 → 触发读者流失风险
- [ ] 战力升级无量化标准 → 引发战力通胀质疑
- [ ] 新设定出现频率 > 每3章1次 → 需确认是否为「画饼」
- [ ] 章节完读率 < 40% → 需检查钩子密度

## 十、科武长篇专用模块（核心资产）

### 10.1 「科武宇宙」设定锚点库

> 写之前先确认这些设定已锁定：

- [ ] 武道等级体系（例：淬体→凝气→化神→……）
- [ ] 机甲/战舰能量体系（例：聚变核心/暗物质引擎）
- [ ] 势力格局分布（至少3方势力+利益冲突）
- [ ] 主角初始战力值与「第一个可量化敌人」战力差
- [ ] 金手指类型（系统/血脉/传承/穿越者记忆）及其限制

### 10.2 长篇节奏基准线

| 节点 | 字数区间 | 必须完成 | 验证问题 |
|:---|:---|:---|:---|
| 签约关 | 0-2万 | 设定锚点+签约门槛达标 | 「读者为什么继续读？」 |
| 推荐关 | 2-8万 | 首个大高潮+体系初显 | 「有追更理由吗？」 |
| 中期关 | 8-30万 | 格局重组+势力洗牌 | 「还有新冲突吗？」 |
| 后期关 | 30-100万 | 终极目标+代价清算 | 「所有账本都清了吗？」 |
| 完本关 | 100万+ | 悬念全解+情感收尾 | 「读者会推荐吗？」 |

### 10.3 可借用的短故事节奏精华

> 以下技巧可嫁接至长篇单卷/副本：

- **「3章副本」结构**：开篇危机→资源争夺→代价清算（适用于限时副本/试炼赛）
- **「单章闭环」结构**：开篇冲突→解谜/战斗→钩子连向主线（适用于支线章节）
- **「情绪爆点」节奏**：每500字需有一个「情绪起伏」或「信息释放」（适用于重点章节）

## 十二、失败模式速查表

| 失败症状 | 根因 | 修复动作 |
|:---|:---|:---|
| 开篇慢热，跳出率高 | 冲突延迟或强度不足 | 强制在前300字加入「致命危机」 |
| 中期水文，完读率下降 | 无新冲突或代价缺失 | 插入「资源争夺」或「势力介入」事件 |
| 战力通胀失控 | 升级无代价或代价不清算 | 重设升级代价体系，每级必须有「后遗症」 |
| 读者质疑「画饼」 | 悬念无后续或承诺延迟兑现 | 制定「悬念追踪表」，每10万字必须有悬念闭合 |
| 章节干巴巴 | 无物理反馈/感官细节 | 强制加入「环境破坏」「装备损耗」「身体负荷」描写 |
| 角色脸谱化 | 配角无独立目标 | 为每个主要配角写「50字独立目标卡」 |

## 补丁使用说明

1. **写作前**：填写「写作执行卡」，锁定本章核心要素
2. **写作中**：对照「动作包」执行，禁止跳步骤
3. **写作后**：运行「章节自检清单」，全部通过方可发布
4. **发布前**：过「平台规则门禁」，规避风险
5. **卡文时**：查「失败模式速查表」，定位根因后修复
