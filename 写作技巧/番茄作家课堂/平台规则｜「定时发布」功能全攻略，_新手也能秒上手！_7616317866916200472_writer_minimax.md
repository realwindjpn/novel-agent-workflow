# 《科武纪元》作家OS · 定时发布补丁 v1.0

> **适用场景**：作家实际写作流程中的操作手册，非理论解读  
> **核心原则**：把平台规则翻译成“做这件事的代价”，让身体记住条件反射

---

## 一、作家操作链（SOP）

```
写作定稿 → [至少提前24h] 上传存稿 → 设置定时时间 → 检查队列是否堵塞 → [发布后] 手动补“作者有话说” → 监控过审状态
```

**关键节点**：上传和发布是两件事，中间夹着审核和排队。你上传了不代表它会按时出来。

---

## 二、物理反馈系统

你每次操作后，平台会给你什么提示？这才是你的行动依据，别靠猜：

| 操作 | 系统会告诉你什么 | 你该怎么理解 |
|:---|:---|:---|
| 上传存稿 | “审核中” | 还没过，还没进队列，还在等 |
| 设置定时 | “已定时”/显示排队序号 | 进队列了，等发布时刻到来 |
| 距发布<30分钟 | 系统锁定，不让你改 | 现在改不了，别硬点 |
| 队列有前置定时章 | “立即发布”被阻塞 | 你想让某章立刻出，但它前面还有章卡着 |
| 审核超过24h | 通常会收到提示或章节仍“审核中” | 你的定时时间可能要废了，需要介入 |
| 实际发布时间晚于设定 | 后台显示实际发布时间 | 可能有延迟，需要盯着 |

**作家行动原则**：看到什么状态就做什么判断，不凭“我觉得”操作。

---

## 三、代价系统（核心）

把每个错误操作和它的代价绑在一起记，这是身体记忆：

| 你如果这样做 | 代价是什么 |
|:---|:---|
| 距发布不足30分钟才发现要改 | **改不了，系统锁死** |
| 前置定时章没发布就点“立即发布” | **物理阻塞，插队失败，后续章全卡死** |
| 上传后不预留审核时间，卡点上传 | **审核延迟=定时时间废掉=断更** |
| 设定时年份设错 | **跨年发稿，全勤清零，流量断崖** |
| 核心反转写进预告关键词 | **读者提前知道底牌，正文悬念全毁** |
| 审核中/待发布的章尝试调顺序 | **系统不支持，直接打乱发布流** |
| 首发章用定时而非立即发布 | **新书期初始审核被后续定时章塞住，断流** |
| 只存1-2章稿就断更 | **系统波动/突发断网=全勤掉** |

## 四、科武长篇可借点

> **标注说明**：“科武借点”指《科武纪元》这类硬科幻长篇可直接使用的策略

### 4.1 保权重·强制日更节奏

**操作**：把定时时间设在平台流量波峰（12:00/18:00/21:00），提前24h+上传存稿，覆盖审核窗口。

**为什么对你有用**：《科武纪元》世界观展开慢，单章信息密度高，定时发布能强制维持稳定更新，避免“你今天懒得写”导致的推荐池降权。

**风险门禁**：每晚睡前检查次日定时队列，发现异常立刻疏通。

### 4.2 科幻悬念钩子·精准筛选读者

**操作**：在定时界面设置自定义预告关键词，释放非核心设定词（如“轨道电梯校准”“基因锁第三阶”），不暴露核心反转。

**为什么对你有用**：精准触发“催更”行为，将平台工具变成追读转化钩子，把路人读者过滤成硬核科幻受众。

**风险门禁**：预告词放设定名词（如武器型号、世界观术语），绝对不放“某人死了”“某秘密被揭穿”这类事件。

### 4.3 审核空窗期·硬科幻复核

**操作**：上传存稿后、等待审核的这段时间，用来做物理逻辑校对、设定一致性检查。

**为什么对你有用**：《科武纪元》涉及大量技术细节，审核等待期≈免费质检期，降低发布后修文风险。

**风险门禁**：发现硬伤立即修，但修改后需重新进入审核队列，时间重新计算。

## 五、短故事/狼人篇可借点

> **标注说明**：“短篇借点”指短故事或狼人篇这类短周期更新可直接套用的策略

### 5.1 首章必须“立即发布”

**操作**：第一话/关键开篇章上传后点“立即发布”，触发初始审核链路。

**为什么对你有用**：短篇/狼人篇节奏快，如果首章用定时，被后续存稿塞住，新书期直接断流，等于白写。

### 5.2 预告关键词=单章钩子

**操作**：每章设置一句非核心悬念的预告词（如“本章节武器解析”“角色背景补完”），引导读者点击催更。

**为什么对你有用**：短篇篇幅有限，每章都是独立钩子，预告词能快速转化点击率。

### 5.3 存稿≥3章保底

**操作**：即使你日更，也要保持至少3章存稿在手，防止突发断网、系统波动导致断更。

**为什么对你有用**：狼人篇/短故事最怕的就是“今天突然写不了”导致全勤断，存稿是保底。

## 六、平台规则→风险门禁转换

| 原始规则 | 作家视角的风险门禁 |
|:---|:---|
| 严格按顺序排队逻辑上传 | **队列门禁**：上传前先看队列，有没有定时章在前面堵着 |
| 距发布<30分钟禁止改期 | **30分钟锁门禁**：发布前30分钟检查清单——时间对不对？内容有没有要改的？最后一次修改机会 |
| 预留≥24小时审核余量 | **审核门禁**：上传时间=预计发布时间-24小时，绝对不卡点上传 |
| 有话说/调序仅支持发布后操作 | **补全门禁**：章节发布后立刻补“作者有话说”，调序只能在发布后做 |
| 首发章设立即发布 | **新书门禁**：第一话/关键转折点必须立即发布，不走定时 |
| 预告关键词不暴露核心反转 | **悬念门禁**：预告词只放设定词，不放事件，不放结果 |

## 七、写作前任务卡字段更新

> **在你动笔前的检查清单里，新增以下字段**：

| 字段名 | 检查内容 | 通过标准 |
|:---|:---|:---|
| **定时上传状态** | 存稿是否提前≥24h上传？ | ✅ 已上传且显示“审核中”或已排入队列 |
| **定时时间锚点** | 定时发布设在哪个时间点？ | ✅ 符合平台流量波峰，且距发布≥24h |
| **队列疏通检查** | 前置定时章是否堵塞“立即发布”？ | ✅ 无阻塞，或已疏通（前置章改为立即发布） |
| **预告关键词** | 是否已自定义？内容是否含核心反转？ | ✅ 已设置，且仅含设定词/非核心悬念 |
| **年份/日期核对** | 年/月/日是否正确？ | ✅ 三项全部核对，尤其是跨年/跨月时 |
| **30分钟锁倒计时** | 距定时发布是否还剩>30分钟？ | ✅ >30分钟，否则停止修改动作 |
| **作者有话说安排** | 是否已规划在发布后补充？ | ✅ 有明确补全时间点（如章节发布后立刻） |
| **调序风险评估** | 是否在审核中/待发布章节前尝试调序？ | ✅ 无此类操作，调序只在发布后执行 |
| **全勤存稿保底** | 当前存稿是否≥3章？ | ✅ ≥3章，有突发情况缓冲 |

## 八、章节自检清单（写作场景版）

> **写完这章后、用定时发布前，快速过一遍**：

**发布前必查（动笔→定稿→上传阶段）**
- [ ] 章节内容已定稿，无“写完再说”的待确认部分
- [ ] 预告关键词已设置，且不含核心反转/底牌
- [ ] 上传时间距预计发布时间≥24小时
- [ ] 定时时间避开30分钟锁定区（距发布>30分钟）
- [ ] 已核对年/月/日格式（尤其跨年/跨月）
- [ ] 队列中无前置定时章阻塞“立即发布”通道

**发布后48小时内监控**
- [ ] 章节是否按定时时间实际发布？（如超时未发布→介入）
- [ ] 审核是否超过24小时？（超时应联系平台或临时转“立即发布”）
- [ ] “作者有话说”是否已补充
- [ ] 是否有读者反馈暴露内容逻辑问题？（有则记录，待修文）

**突发情况应急**
- [ ] 临时要插队：是否已先疏通前置定时章（改为立即发布）？
- [ ] 要调顺序：是否所有相关章节都已发布或审核通过？待发布/审核中章绝对不调
- [ ] 发现断更风险：是否还有存稿≥3章可用？

## 九、人物口吻·段落节奏·章末钩子（定时发布场景下的创作建议）

### 人物口吻适配

定时发布场景下，你的章节是“定时投喂”的，读者的期待感是跟着时间锚点走的。

**可用口吻**：
- 章节末用主角视角留下悬念疑问（如“基因锁第三阶段……为什么偏偏是我？”）
- 用未解答的设定疑问绑定读者好奇心，等待下一章定时发布
- 预告词用设定术语（如“曲率引擎原理”），引导期待型读者

**禁用口吻**：
- 章末留“开放式结局”但不设钩子，等读者自己追——平台数据会告诉你没人催更
- 预告词用事件描述（如“主角发现真相”），直接剧透核心反转

### 段落节奏适配

| 章节类型 | 定时发布节奏建议 |
|:---|:---|
| **高悬念章** | 结尾留核心悬念+预告词引导催更，定时设为流量波峰 |
| **世界观展开章** | 结尾留设定钩子（如“新武器原理”），预告词用术语，筛选硬核读者 |
| **战斗/冲突章** | 高潮点卡在发布前30分钟，定时发布后读者正好追读峰值 |
| **日常/过渡章** | 结尾埋下一章冲突伏笔，用预告词预告“冲突升级”，防止订阅下降 |

### 章末钩子适配

**定时发布专用钩子公式**：
> “XX秘密/技术/人物身份”——预告词放这个  
> 章节内埋钩子但不解谜——正文悬念保留  
> 读者点击催更=追读转化=平台推荐权重提升

**绝对不能用的钩子**：
- 预告词+正文双重剧透（读者已知答案，正文变流水账）
- 悬念放到章末却不设预告词（没人知道有悬念，自然不催更）

## 十、补丁执行原则

> **最后一条，也是最重要的一条**：

**把定时发布当作“写完小说后的物流系统”**：
- 你的核心工作是写好内容
- 定时发布是保证内容按时到达读者手里的工具
- 工具坏了（断更/卡审核/队列堵塞）不等于小说差，但会让平台算法认为你“差”

**每次操作前，问自己三个问题**：
1. 这个操作有系统提示吗？（有→执行；无→停手）
2. 我留够时间了吗？（≥24h审核余量）
3. 我留够存稿了吗？（≥3章保底）
