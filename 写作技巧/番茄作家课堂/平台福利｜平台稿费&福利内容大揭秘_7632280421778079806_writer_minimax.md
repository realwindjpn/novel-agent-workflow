# 《科武纪元》作家OS补丁 v2026.01

## ⚡ 核心收益逻辑（作家执行视角）

> **你的收益 = 读者读完的字数 × 广告转化率**
> 
> 不是"写多少字给多少钱"，是"读者跟着读多深，广告才跟着曝光多久"

## 一、每日执行指令（强制）

### 【起手式】章节任务卡字段更新

| 字段 | 填写要求 | 科武长篇适配 |
|:---|:---|:---|
| **触发事件** | 本章开头第一个动作事件（≤15字） | 例："林昭启动报废机甲" |
| **执行目标** | 主角本章节要完成什么事（≤20字） | 战力验证/情报获取/资源争夺 |
| **物理反馈** | 能量消耗/装备损耗/环境交互的具象数据 | 机甲剩余能量槽、弹药基数、环境毒性值 |
| **代价清单** | 突破/情报/资源的隐性代价（时间/关系/风险三选一） | 冷却期、反噬、暴露风险 |
| **章末悬念** | 可验证的未解问题（非开放式追问） | "他发现操控者不是人类——那是谁？" |
| **改编预留** | 本章可独立成短视频片段的核心画面 | 机甲启动第一视角/战斗特写 |

---

### 【日更节奏指令】

```
每章结构：触发事件(10%) → 执行过程(60%) → 代价显现(20%) → 悬念收尾(10%)
字数分配：4000字章=400+2400+800+400
          6000字章=600+3600+1200+600
```

**章末钩子模板（三选一）**

| 钩子类型 | 执行句式 | 案例 |
|:---|:---|:---|
| **危机悬念** | 主角发现/解决→新威胁浮现 | "他刚躲过追击，却发现弹药只剩三发——而前方还有十二架追兵。" |

## 三、章节自检清单（每章发布前必做）

```
□ 1. 核心设定是否在本章抛出？（读者能理解世界观基础）
□ 2. 首个强冲突是否已触发？（前3章必须有"必须读下去"的理由）
□ 3. 主角动作链是否完整？（触发→执行→结果，三段式清晰）
□ 4. 物理反馈是否具象化？（能量消耗/装备损耗/环境威胁有数字感）
□ 5. 代价是否明确绑定？（战力突破≠无代价）
□ 6. 章末悬念是否可验证？（读者知道"明天会发生什么"）
□ 7. 字数是否达标？（日更4000/6000，且为10的整数倍）
□ 8. 是否预留改编画面？（核心场景可独立截取成短视频）
□ 9. 打赏触发是否自然？（情感锚点驱动，非诱导话术）
□ 10. 内容是否通过自检？（无敏感词/版权素材/违规内容）
```

## 四、失败模式速查表

| 失败类型 | 特征 | 修复方法 |
|:---|:---|:---|
| **数据断崖** | 某章读完率骤降 | 检查是否有"无意义过渡章"或"设定堆砌"；加入可量化冲突事件 |
| **跳章率高** | 读者跳过中间章节 | 章末悬念必须关联主线；删除纯信息交代章节，改用"实战中揭示" |
| **打赏为零** | 互动收益长期为0 | 增加主角情感锚点（保护对象/复仇对象/信念对象）；增加配角死亡/牺牲场景 |
| **审核未过** | 字数不计入/下架 | 次月1日前48小时不发布新章节；发布前使用平台敏感词工具检测 |
| **星火计划落选** | 万字读完率不达标 | 缩短铺垫节奏，每章必须有"实质性剧情推进"；删除冗余世界观章节 |
