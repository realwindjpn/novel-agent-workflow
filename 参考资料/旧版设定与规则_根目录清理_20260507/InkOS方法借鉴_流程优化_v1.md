# InkOS 方法借鉴：现有小说流程优化 v1

> 目标：学习 InkOS 的“工作台、状态管理、风格分析、市场雷达、流程门控”思想，优化现有《科武纪元》流程。  
> 边界：不安装 InkOS，不迁移主流程，不替代六角色外审。

---

## 1. 可借鉴的方法

从 InkOS 展示信息抽象出 6 个方法：

1. **Studio 工作台**：把章节、大纲、素材、进度、审核放在同一视图。
2. **TUI 仪表盘**：用全屏交互面板快速查看项目状态。
3. **Book Management**：以“书”为单位管理卷、章、状态，而不是散文件。
4. **Chapter Outline Editing**：章节写作前明确目标、禁止项、承接点。
5. **Writing Style Analysis**：写后做风格、AI味、解释腔、术语密度分析。
6. **Guardrail / Process Control**：用门禁防止跳章、未审推进、跑偏。

这些与我们现有机制吻合。我们缺的是“可视化统一面板”和“指标化预检”。

## 3. 可立即优化项

### 3.1 增加“小说状态看板”

路径建议：

`/root/workspace/科武纪元/审核记录/项目看板.md`

内容：

```md
# 科武纪元项目看板

## 写作线
最新章节：第XXX章
下一章：第XXX章
门禁：GATE_OK / BLOCKED

## 上传线
已投稿连续至：第XX章
下一待上传：第XX章

## 第五卷进度
209-258：已完成 X / 50
剩余：X章

## 异常
- 缺WAL：
- 缺记忆卡：
- 缺外审：
- 字数不足：
- 末行异常：
```

### 3.2 增加“章节状态索引”

路径：

`/root/workspace/科武纪元/审核记录/chapter_status.json`

字段：

```json
{
  "chapter": 243,
  "title": "反扫",
  "word_count_cn": 4018,
  "draft_path": "新版/第243章.md",
  "review_status": "PASS",
  "roles": ["editor", "reader", "military", "science"],
  "wal": true,
  "memory_card": true,
  "gate_next": 244,
  "upload_status": "not_uploaded"
}
```

用途：后续可接 InkOS/Studio/自建HTML看板。

### 3.3 增加本地风格预检

在外审前先跑本地脚本，减少模型消耗。

检测项：

- 中文字数 ≥ 3000
- 首行标题
- 末行 `（本章完）`
- AI味高频词
- 文艺比喻/咏叹调禁词
- 术语密度
- 对话占比
- 解释段连续长度
- 大纲关键词命中

输出：

`/root/workspace/科武纪元/审核记录/本地预检/第XXX章.md`

### 3.4 增加“素材卡”机制

每条素材转成固定格式：

```md
# 素材卡：标题
来源：
时间：
可信度：
一句话：
是什么：
怎么用：
战术/产业意义：
可映射章节：
禁用风险：
```

InkOS 的素材/文档编辑可后续承载这些卡片。

### 3.5 增加“章节写作前任务卡”

现有 WAL 已有部分功能。优化为更清晰的卡：

```md
# 第XXX章任务卡
目标：
承接：
必须发生：
禁止发生：
技术点：
人物点：
章末钩子：
验收标准：
```

WAL 保留，任务卡可由上下文脚本自动生成。

## 5. 优化路线

### v1：只加文件级看板

- 生成 `项目看板.md`
- 生成 `chapter_status.json`
- 不影响写作。

### v2：加本地风格预检

- 写 `local_style_check.py`
- 每章外审前跑。
- 将问题写入本地预检记录。

### v3：加素材卡接入

- 接素材采集增强计划。
- 每日素材自动转小说素材卡。

### v4：InkOS 沙盒对接

- 小说阶段结束后。
- 只导入3章样本。
- 测可视化与导出。

---

## 6. 结论

可学习 InkOS 的“工作台化”和“指标化”方法。  
现阶段最值得做的是：

1. 项目看板
2. 章节状态索引
3. 本地风格预检
4. 素材卡

这些能增强现有流程，不破坏门禁。  
InkOS 本体等小说阶段结束后再沙盒测试。
