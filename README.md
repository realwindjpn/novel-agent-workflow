# Novel Agent Workflow：我参与过的本地写作工作台

这个仓库起点是 [realwindjpn/novel-agent-workflow](https://github.com/realwindjpn/novel-agent-workflow)：它把小说创作当成一套文件优先、状态机驱动的工作流。创意、评审、章节、发布凭证都应该能落到文件里，被人和工具一起检查，而不是只留在一段聊天记录里。

我没有把原项目重新发明一遍。我参与做的，是把这套偏命令行和协议层的能力接到一个能日常使用的本地网页工作台上：能选书、能写、能自由聊、能在确认后回到正式流程，也能在本机安全地管理自己的书库。

## 我主要参与了什么

最开始只是把原本的工作流放进浏览器里跑；后来事情慢慢变成了一个完整的本地创作桌面。

- 做了网页端运行器和 Windows 一键启动入口，让项目不必从背命令开始。
- 接入本地 MCP 桥接：网页只向当前选中的书发请求，真正的状态变化仍由 `novel-workflow mcp --root <book>` 处理。
- 做了自由创作模式：可以先用自然语言聊人物、方向和片段，再把确认过的内容交给正式工作流。
- 做了持续对话和浮动工作台：第一句先在主界面得到回复，连续聊下去时再迁移到可拖动、可缩放、可最小化的浮动窗口。
- 做了本地书库、选书卡片、同名处理和可恢复回收区；误收进去的作品不需要立刻消失。
- 把本地可写页面与公网演示页面隔开：能分享演示，但不会把本机书库暴露出去。

这不是“点一下就自动写完一本小说”的工具。我更在意的是：灵感可以自由生长，真正写入项目之前仍然有确认、有证据、有可以回头检查的过程。

## 怎么开始用

在 Windows 上打开终端，进入仓库根目录（这里应当能看到 `pyproject.toml` 和 `一键启动.cmd`）：

```powershell
cd <仓库目录>
.\一键启动.cmd
```

浏览器会打开本地工作台。默认使用：

```text
http://localhost:8080
```

如果 `8080` 已被其他程序占用，可以换一组端口：

```powershell
.\一键启动.cmd --port 9090 --public-port 9091
```

这时访问 `http://localhost:9090`。如果只想在本机使用、不需要临时公网链接：

```powershell
.\一键启动.cmd --no-tunnel
```

启动器会优先使用仓库里的 `.venv`，没有时再寻找系统 Python。完整模式需要 Python 3.11+；需要公网演示时还要把 `cloudflared` 放进 `PATH`。

## 先分清两个页面

| 地址 | 我把它当成什么 | 会不会写入本机书库 |
| --- | --- | --- |
| `http://localhost:8080` | 日常创作入口，本地 MCP 模式 | 会 |
| `http://localhost:8081` | 浏览器内存演示页 | 不会 |
| Cloudflare 临时链接 | 给别人看界面和流程的演示页 | 不会 |

`8080` 才是我平时真正使用的入口。它会带有“本地 MCP · 可写磁盘”的标记；`8081` 与临时公网链接只运行浏览器内存里的版本，即使页面看起来一样，也不应把它当作书库的入口。

## 一次日常创作是怎样走的

### 1. 选书或新建一本书

打开本地页面后，点击顶部的“换库”选择书库目录。默认书库是：

```text
<仓库目录>/book
```

然后打开书库列表：可以选择已有作品，也可以新建。每本书都有自己的 `workflow.json`、章节目录和 `.novel-workflow` 状态文件。选中后点击“继续创作”，网页才会为这本书启动对应的 MCP 子进程。

同名书不会被悄悄覆盖：页面会让你选择打开已有作品、新建一份带后缀的副本，或者取消。

### 2. 在工作台里做正式流程

编码模式保留原项目的工作流能力。你可以用终端输入 `novel-workflow` 命令，逐步推进创意、提纲、章节、评审和发布。常用的辅助命令有：

```text
help / ls / cat / tree / clear
```

这里的重点不是把命令藏起来，而是让命令、文件和状态仍然对得上：网页只是入口，真正的规则仍然由原有工作流核心执行。

### 3. 先自由聊，再决定要不要落入项目

切换到“自由创作”后，可以直接说你想写的方向，例如人物关系、开场气氛、一个冲突，或者只是“你来决定”。

第一轮自然语言回复会留在主工作区，方便快速试探。连续进行第二轮自然对话时，会话会迁移到右下角的浮动窗口；它的位置和大小会记住，也可以拖动、缩放、最小化或关闭。已知命令和无效的 `novel-workflow` 命令仍留在终端，不会被误当成聊天。

自由创作不是绕过流程的捷径。系统会整理对话中的有效证据；在方案完整、经过确认之前，它不会改动核心工作流。确认后的方案还要经过两道门：先在浮动窗口提交，再在主工作台执行。

自由创作页右上角的“流水线”和“文件”会打开侧边抽屉。文件抽屉打开后，可以直接在它自己的标题栏点“收起”，不必再去够被遮住的顶部按钮。

### 4. 误删时先放进回收区

书库里的“移入回收区”不会直接永久删除作品。它会把整本书移动到：

```text
<书库目录>/.trash/<时间戳>__<原目录名>/
```

同时写入 `.trash-info.json` 作为本地标记。回收区里可以恢复作品；如果原目录名已经被重新使用，恢复后的目录会自动带上 `（恢复1）`、`（恢复2）` 之类的后缀，永远不覆盖现有书。

网页里没有永久删除按钮。确实要清理时，我会在 Windows 文件管理器中直接删除 `.trash` 下对应的目录。

## 本地 MCP 的边界

本地网页不是把任意文件系统开放给浏览器。它只服务当前选择的书库和当前打开的书，且有几层刻意保留的限制：

- 本地 API 使用每次启动生成的令牌，并检查请求来源。
- 只允许受限的 MCP 方法，网页不能自行初始化或接管底层连接。
- 书库和回收区只接受其根目录下的直接子目录；符号链接、目录联接和路径逃逸会被拒绝。
- `8081` 与临时公网页没有 `/api/local/*` 路由，访问这些接口会得到 `404`。
- 退出启动器或按 `Ctrl+C` 时，会关闭网页服务、MCP 子进程和临时隧道。

这些限制不一定让演示看起来最“无感”，但它们能避免“我只是打开了一个网页，结果把本机目录和长期创作资料暴露出去”这种事。

## 目录大致长什么样

```text
<仓库目录>/
├─ src/                 原项目的 Python 工作流核心
├─ web/                 我参与扩展的浏览器工作台
├─ scripts/             启动器、本地 MCP 桥接和辅助脚本
├─ tests/               Python 与 JavaScript 回归测试
├─ book/                默认本地书库（可用 --library-root 改到别处）
└─ 一键启动.cmd          Windows 启动入口
```

网页端的进一步实现说明在 [web/README.md](web/README.md)；协议层的说明在 [docs/MCP.md](docs/MCP.md)。它们适合需要看细节的时候再打开，日常使用从本页的启动命令开始就够了。

## 我保留的原项目边界

这个分支是在原项目工作流核心上继续做的本地化和产品化，不把所有基础能力都归为我个人完成。原项目提供了文件优先、状态机、角色分工、评审证据和发布闸门；我参与的重心在于把这些规则接到可操作的网页、本地协议和创作交互中。

如果你只是想写作，打开本地 `8080` 页面、选一本书、从自由创作或正式工作台开始即可；如果你需要验证过程，文件、状态和命令仍然都在本地，随时可以回看。
