# 《科武纪元》编辑学习官｜《定时发布功能全攻略》规则提炼

## 1 课程核心判断（≤6条）
1. **定时发布是流量基建工具**：不提升单章质量，但直接决定全勤达标率、推荐位稳定性与读者追读预期。
2. **审核队列具有强顺序性**：前置定时章未发布，后续“立即发布”会被物理阻塞，无法插队。
3. **时间窗口存在硬性锁死**：距发布不足30分钟系统锁定，无法修改；审核最长需24小时，卡点必断更。
4. **预告功能是预期管理接口**：自定义预告关键词可精准引导“催更”行为，转化为追读数据。
5. **运营动作必须与发布解耦**：“作者有话说”与“章节调序”不支持定时，需发布后手动操作。
6. **容错率极低**：年份误设、队列堵塞、审核延迟任一环节失误，直接导致断更/掉全勤/流量断崖。

## 2 可执行编辑规则（按文章实际内容取舍）
| 维度 | 规则（基于定时发布机制反推） |
|:---|:---|
| **平台规则** | ①严格按“顺序排队”逻辑上传；②距发布<30分钟禁止改期；③预留≥24小时审核余量；④有话说/调序仅支持发布后操作。 |
| **开篇** | 首章/关键开篇必须设为“立即发布”触发初始审核，避免被后续定时章节阻塞导致新书期断流。 |
| **节奏** | 定时时间即连载节奏锚点。需按平台流量波峰（如12:00/18:00/21:00）预设，且存稿上传时间需早于发布时间24h+。 |
| **冲突** | 章节冲突爆发点需与“预告关键词”绑定（如“明日解锁：反物质过载”），利用催更预告提前蓄水，但定时阶段严禁剧透核心反转。 |
| **人物** | 人物设定补全/互动需通过“作者有话说”在章节正式发布后手动追加，不可依赖定时功能预埋。 |
| **题材** | 热点稿强时效性，必须提前存稿对冲审核延迟；长篇科幻依赖定时保“稳定更新”标签以获取长尾推荐。 |
| **改编** | 定时发布形成的连续更新数据与读者催更率，是平台评估IP商业价值（含短剧/漫画改编）的基础权重指标。 |

## 3 科武适配
**✅ 可用点**
- **长篇连载保权重**：《科武纪元》世界观展开慢、单章信息密度高，定时发布可强制维持日更/双更节奏，避免人为断更导致推荐池降权。
- **科幻悬念预告**：利用“自定义预告关键词”释放非核心设定词（如“轨道电梯校准”“基因锁第三阶”），精准筛选硬核科幻读者，提升催更转化率。
- **审核缓冲期打磨**：提前24h上传存稿，可利用审核空窗期进行硬科幻设定复核、物理逻辑校对，降低发布后修文风险。

**❌ 不可硬套点**
- **不可用定时追热点**：科幻长篇非热点稿，强行卡点发布易因审核延迟导致“设定未铺垫完就断更”，破坏长篇叙事连贯性。
- **预告词不可过度剧透**：科幻底牌（如“曲率引擎原理”“最终反派身份”）若写入预告关键词，将直接摧毁长篇悬疑结构。
- **不可依赖定时调序**：科幻长篇常需根据读者反馈微调章节顺序，但“审核中/待发布定时章”绝对不可调序，需发布后操作，否则打乱发布流。

## 4 编辑检查表（10条以内）
- [ ] 存稿是否提前≥24小时上传，覆盖最长审核周期？
- [ ] 定时时间是否避开发布前30分钟锁定区？
- [ ] 是否核对年/月/日格式，杜绝跨年误设？
- [ ] 队列中是否存在“定时章”阻塞后续“立即发布”？
- [ ] 预告关键词是否已自定义且无核心设定/反转剧透？
- [ ] “作者有话说”是否安排在章节正式发布后手动补充？
- [ ] 审核中/待发布章节是否未尝试后台调序？
- [ ] 突发插队章节是否已先将前置定时章改为“立即发布”疏通？
- [ ] 定时发布后是否监控实际过审状态（如12:05未发即介入）？
- [ ] 全勤保底存稿量是否≥3章（防系统波动/突发断网）？

## 5 对作家角色的输入要求
| 维度 | 输入标准（基于平台机制与创作流） |
|:---|:---|
| **动作链** | 写作定稿 → 上传存稿 → 设置定时时间 → 检查队列阻塞 → 发布后补“有话说” → 监控过审状态。形成标准化SOP，杜绝临时操作。 |
| **物理反馈** | 后台状态提示（审核中/已定时/已发布/30分钟锁定/队列阻塞报错）。作家需以系统提示为唯一操作依据，不凭主观判断。 |
| **代价** | 卡点上传=审核延迟=断更/掉全勤；不疏通队列强行插队=后续章节永久卡死；误设年份=流量断崖+全勤清零。 |
| **钩子** | 利用“预告关键词”在定时界面释放非核心悬念词，绑定读者“催更”行为，将平台工具转化为追读转化钩子。 |
| **读者预期** | 定时发布提供确定性更新节奏；预告词管理追读预期；审核延迟需通过存稿平滑过渡。作家输入必须保证“预告-发布-内容”预期一致，禁止预告与正文脱节。 |
